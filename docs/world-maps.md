# Global map display and selected-area downloads

The map uses OpenFreeMap vector tiles for worldwide geographical context. Regional depth bounds, holding evidence and hazards are separate assessment inputs. Browsing a new area does not create nautical coverage or establish an anchoring clearance.

The optional depth display also includes coarse GEBCO WMS imagery below zoom 13, and marks include the OpenSeaMap community overlay. Bedding adds EMODnet Geology's European 1:1M/1:250k substrate imagery at overview zooms 4–12, bounded to the European region. These are online display layers. They are excluded from the offline basemap download and never passed to the assessment engine. GEBCO explicitly excludes navigation and safety-at-sea use; OpenSeaMap is not complete authoritative hazard coverage. EMODnet substrate colours describe broad-scale sediment classes, not a verified anchor footprint, holding quality or habitat permission; its provider legend is linked in the layer details. Reviewed regional bedding polygons remain above this contextual imagery.

## Download contract

`apps/mobile/src/lib/worldMaps` provides platform-specific storage through a shared deterministic download coordinator:

- `estimateMapArea({ bounds, maxZoom? })` estimates vector tile count and bytes. The default reduces detail to stay within the estimate; actual bytes are enforced while downloading.
- `downloadMapArea({ name, bounds, maxZoom?, id? }, onProgress?, signal?)` downloads an explicitly selected area. Supplying its original `id` resumes or repairs an existing area.
- `listMapAreas()`, `cancelMapArea(id)` and `deleteMapArea(id)` manage local areas.
- `verifyMapArea(id)` checks stored resource sizes and SHA-256 hashes; missing or corrupt files make the area partial and repairable.
- `MapArea.usableZoom` is the highest fully downloaded zoom covering the selected area, including its label glyph ranges. Zero is a valid coarse map; undefined means it is not yet usable. The field is derived for older manifests too. `attribution` is retained with each saved area.
- `loadWorldMapStyle(online)` supplies cached complete or usable partial areas, beneath live detail when online. `subscribeMapAreas(listener)` updates map views when usable levels, completion, repair or deletion changes. Rendering updates are throttled to once per second and preserve existing live sources.

Downloads are limited to one area at a time, three concurrent requests, 3,000 tiles and 50 MB. Coarse zoom levels and their labels finish before finer levels start, so usable partial maps remain available after pausing or losing the connection. Service errors, rate limits and cancellation stop further work. Verified partial resources remain resumable; an area becomes complete only after all requested tiles and required label glyphs have been written. Each area pins the provider's dated tile dataset. A new download does not replace an existing complete area; keep that area until the replacement is complete. A refresh date prompts review after a week; downloading display data does not extend regional forecast validity.

Cached map geometry sits below online sources: successful live tiles retain their finer detail, while provider failures reveal saved coverage without a manual offline switch. Areas without downloaded data remain blank or coarse where only coarse tiles are available; display coverage does not establish nautical evidence. Local names take priority over English/transliterated alternatives. Glyph discovery follows exactly the same rule for Japanese, Chinese, Thai, Greek and other BMP scripts. Older downloaded areas retain their Latin-first label policy so that their existing cached fonts continue working offline; a new download uses local names. Multilingual labels can dominate a small download, so estimates reserve 20 MB for font blocks; actual size remains bounded by the 50 MB cap. Font rendering and shaping still depend on the platform; the cache does not add right-to-left shaping support.

Native apps store map files in their private document directory and metadata in SQLite. Native file resources are verified before first use each launch; app writes/deletes invalidate this in-process check. Native URL transforms use only verified local font ranges, leaving uncached labels to load online. Browser previews use Cache Storage and a MapLibre protocol that verifies each cached resource before rendering it; glyphs resolve locally first, then online if permitted. Browser downloads use the configured API's fixed-host `/v1/maps/resource` proxy to supply the required application User-Agent; native downloads and native online resource requests identify the app directly. Normal browser online viewing goes directly to the provider, as in its browser integration guide.

Production web exports also cache the application shell, including the MapLibre worker and its imported module, so opening a saved map for the first time or reloading the app can work offline. `npm run export:web --workspace=@anchor-buddy/mobile` runs the post-export step automatically. Serve `apps/mobile/dist` at the origin root over HTTPS or localhost; `.js` and `.mjs` files must have a JavaScript MIME type. The first visit must be online. A map download waits for the shell to finish installing before proceeding. Each build's shell is complete and SHA-256 checked before activation; interrupted updates preserve the previous shell. Updates activate after tabs using the prior version close. API responses, charts and provider imagery are not cached by this service worker.

For local offline testing, run `python3 -m http.server 8082 --directory apps/mobile/dist`, visit `http://localhost:8082` online, and download an area. Switch off the network, open that saved map and reload the page. Browser storage can still be cleared or evicted; downloaded maps should be checked before departure. Metro development (`npm run web`) deliberately does not register the shell worker and still requires its server. Keep development and exported previews on different ports/origins. If an exported origin is later reused for Metro, its worker update receives a development cleanup worker: it removes only app-shell caches, unregisters itself and reloads the app into Metro. Saved map and user data are preserved. Always use the full `export:web` command; its post-step replaces that development worker with the generated production worker.

Native binaries contain their application code locally. Full native rendering and device acceptance remain required; JavaScript/Hermes export does not test native file loading or background behavior.

## Provider sources

- [OpenFreeMap integration guide](https://openfreemap.org/quick_start/) documents global browser/native use.
- [OpenFreeMap terms](https://openfreemap.org/tos/) permit bounded offline areas, at most four parallel requests and an identifying User-Agent. The implementation uses three requests and enforces both the tile and byte limits. Public OpenStreetMap raster servers are not used for these downloads.
- [GEBCO WMS documentation](https://www.gebco.net/data-products/gebco-web-services/web-map-service) documents the global imagery and its limitations. The live service's EPSG:3857 projection and image/CORS response were checked during implementation.
- [OpenSeaMap server documentation](https://wiki.openseamap.org/wiki/OpenSeaMap-dev%3AServer) identifies its community seamark layer.
- [EMODnet web-service documentation](https://emodnet.ec.europa.eu/en/emodnet-web-service-documentation) identifies the Geology substrate WMS. Its declared EPSG:3857 support, transparent PNG output and browser CORS were checked during implementation.

Attribution remains in the map. No provider passwords, tokens, planetary tile archives or downloaded world datasets are committed to the repository.
