# Q35 explicit stop confirmation

Stopping requires a named-session confirmation. Keep monitoring/cancel issues no command. A synchronous latch blocks duplicate stop commands; fresh native status is checked before the stop and the session must still match the confirmation. A fresh post-command read must show no active/running service before completion. Changed lifecycle, newer status events, unavailable service or inconsistent running state cannot grant a stale confirmation. Failure retains a retry and unverified status. Alert acknowledgment remains separate.

Sol independently reviewed the watch boundary and found no blocker; its defensive native-availability/service-state/lifecycle feedback suggestions were incorporated. The isolated real WatchScreen/native-substitute harness passed 9/9 including cancel, delayed stop, exactly one command, failed stop followed by explicit retry, and changed session rejecting the old confirmation. Browser production entry remains unavailable; no automatic navigation action arms/stops/recenters the watch. Actual device stop transition remains a Q36/Q37 gate.

Final boundary audit and repairs: active stop requires a nonempty matching session ID; unavailable post-stop status cannot confirm success; post-stop idle with a different or empty session ID is rejected, while an absent ID is accepted when the native service clears it. Events observed while stop is in flight are tracked: an active, inconsistent, unavailable or different-session event invalidates completion, and subsequent stale events are not accepted during that attempt. A consistent expected idle event and matching/cleared post-read can complete normally. The isolated watch/forecast harness passed 16/16 after these changes, including missing ID, unavailable post-read, newer active session during delayed stop, different/empty/absent post-read ID and the normal successful stop.

Residual protocol limit: native `Watch.stop()` does not accept an expected session ID, so the JavaScript pre-read cannot provide atomic compare-and-stop semantics if a session changes between the read and native command execution. Resolving that requires a separately reviewed native protocol change; no physical-device verification is claimed here.
