## Observed gap

SavedScreen invokes void deletion callbacks and dismisses immediately. Map deletion removes assets before metadata writes; a late failure can leave partial deletion, so retaining the card alone is not rollback.

## Implement

Define deletion outcomes as complete, unchanged failure or partial cleanup pending. Await commands for searches/maps/evidence/drafts, reconcile metadata and asset availability after failure, and make retries idempotent. Do not promise rollback of removed assets; prevent opening a partially removed resource as if intact.

## Acceptance criteria

1. Dialog names the exact resource and blocks duplicate delete submissions.
2. Failure before mutation retains the item and dialog. Partial failure displays cleanup pending/unavailable with retry, and reload does not falsely present the resource as intact.
3. Success removes only the chosen resource and restores sensible focus.
4. Active/unverified watch evidence protections are preserved and refusal stays visible.

## Focused verification

Inject failure before removal, after some assets, and before/after metadata persistence; retry and reload each state. Verify delayed/successful/protected deletes and keyboard focus. Storage reviewer checks partial-state reconciliation.

For UI tasks, record actual viewport dimensions and inspect the changed control in context. For nontrivial state transitions, include a failure-path check. Use existing tests before adding new ones; do not treat mocked/native-reference tests as physical-device evidence.
