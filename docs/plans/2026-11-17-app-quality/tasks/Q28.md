## Observed gap

Saved displays individual map sizes without total storage context. regionalDataCore retains eight cache entries, and the UI does not clearly distinguish automatically cached from deliberately retained evidence.

## Implement

Show known map/data usage and browser capacity where available. Define explicit automatic-versus-retained behavior and offer targeted delete/retry for quota failures; reuse existing storage contracts. Introduce explicit retention metadata through a reviewed migration. Existing savedAt is also set by discovery and cannot prove explicit retention; preserve ambiguous legacy entries as protected legacy records until the user chooses, rather than automatically evicting them.

## Acceptance criteria

1. A new live search cannot silently evict evidence explicitly saved by the user.
2. Unknown native/browser capacity is labelled unknown; estimates are not guarantees.
3. Quota failure retains existing data and provides a useful manage-storage/retry action.
4. Retention changes never refresh source expiry or delete saved maps automatically.
5. Legacy entries are not classified as explicitly saved solely from savedAt, and ambiguous prior data is preserved until an explicit retention decision.

## Focused verification

Eight-plus-region retention and quota failure/retry tests; verify byte totals without double-counting shared assets. Persistence policy review before schema changes.

For UI tasks, record actual viewport dimensions and inspect the changed control in context. For nontrivial state transitions, include a failure-path check. Use existing tests before adding new ones; do not treat mocked/native-reference tests as physical-device evidence.
