# Live area discovery

`POST /v1/regions/discover` takes `{center:[longitude,latitude],radiusNm,name?,timezone?,from?,until?}`. Radius is 0.25–25 nautical miles; coordinates are rounded to four decimal places; stay is at most 30 days. Dates are ISO timestamps with timezones. Optional `timezone` is a validated IANA display timezone and does not alter the supplied stay instants. The response includes `{pack,providers,notices,requestedArea,partial,mapContext?}`. Provider status fields are `id`, `name`, `status` (`available`, `partial`, `unavailable`, `disabled`, `not-covered`), `message`, and optional `attribution`, `documentationUrl`, `retrievedAt`, `validUntil`, `license`.

This endpoint requests real public data for the selected area. It never substitutes demonstration places when a provider fails. A stable request-area hash identifies the pack; the retrieval timestamp and a content hash identify the version. The API keeps 64 recent versions in memory and a bounded disk cache, so `/v1/search` can restore cached versions after restart. Mobile persists evidence independently. Every live snapshot has `validation.status=unreviewed`, explicitly incomplete weather coverage, and no manufactured chart depths, tariffs, tide/current relationships, habitat, jurisdiction or clearance evidence. Shared assessment cannot return a passing anchoring recommendation from live discovery alone. Reviewed regional NOAA analysis packs are a separate ingestion/review workflow. Community seamarks are display features, not complete chart hazards.

The API has no demonstration route or built-in synthetic region. Runtime discovery, search, estimates and downloadable artifacts reject synthetic or mixed-source records. Legacy caches without explicit real-source declarations are not restored. Synthetic fixtures are isolated under tests and the domain testing entry point.

MET Norway supplies global point-model wind and Oceanforecast significant-wave estimates in its Northwestern European marine models. NWS raw grids and active alerts supplement US locations. Source intervals and missing fields are preserved; forecasts are never extended beyond their returned interval. Wind blending prefers an available NWS value, then MET wind; waves prefer NWS, then regional MET Oceanforecast, then explicitly configured Open-Meteo. Missing waves/current/swell never mean calm conditions. Significant wave height is not the maximum height of an individual wave. Oceanforecast can snap to another sea-grid coordinate; the actual point is shown in its provider message. Mediterranean and Asian wave data remain unknown by default. NWS active warnings do not establish future warning completeness. No coverage rectangle is treated as reviewed spatial evidence.

`mapContext` contains optional real EMODnet DTM and seabed samples at the selected European point. Source sign, LAT reference, scale, vintage and attribution are retained. These scientific display samples are never copied into assessment `depths`, `holdingAreas`, hazards or coverage. Valid empty responses stay empty. The UI can retain/display these values offline with their original source dates; they cannot establish clearance, holding ground or anchoring permission.

## Public-service policies

- [MET Norway terms](https://api.met.no/doc/TermsOfService), [Locationforecast update guidance](https://docs.api.met.no/doc/locationforecast/FAQ.html) and [Oceanforecast documentation](https://api.met.no/weatherapi/oceanforecast/2.0/documentation): CC BY 4.0/NLOD attribution, identifying User-Agent, four-decimal coordinates, cached responses until `Expires`, conditional revalidation and bounded traffic. The 2026-11-05 policy requires waiting at least half the model update interval for identical Locationforecast requests. The gateway waits at least three hours everywhere, including Nordic locations, or until a later server expiry before repeating an identical request. This minimum requery interval never extends source expiry: held data retains its original dates and remains visibly expired when applicable. Oceanforecast follows response expiry. Both work commercially without API secrets under their attribution license. End-user IPs are not forwarded.
- Boating POIs use identified, bounded Overpass POST requests with a 600-feature cap and [OSM attribution/ODbL](https://www.openstreetmap.org/copyright). Development selects the [Dresel Europe extract service](https://ovp.dresel.systems/) when the complete search disk fits its [Geofabrik Europe outline](https://download.geofabrik.de/europe.poly), otherwise the OSM-listed [VK Maps global service](https://maps.mail.ru/osm/tools/overpass/). The Europe outline is a routing aid, never nautical coverage. The public project lists both services in its [instance register](https://wiki.openstreetmap.org/wiki/Overpass_API#Public_Overpass_API_instances). Regional service requests are serial, cached and identified; no automatic mirror retry chain is used. Fees, depths, access and seabed tags remain unverified notes. The selected area coordinates go to the selected operator, including VK Maps for the global default; no boat profile or user IP is forwarded.
- `OVERPASS_URL` overrides all regions with an explicitly selected managed/self-hosted service. `OVERPASS_EUROPE_URL` optionally overrides just Europe. In production each unconfigured public default is disabled. Review provider terms and capacity before deployment; the [main public Overpass service](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html) is not a dependable commercial backend. Keep credentials out of endpoint URLs: arbitrary path-embedded API-key adapters are not implemented. HTTP 429/406/5xx trigger cooldown/backoff, not aggressive retries.
- [EMODnet services](https://emodnet.ec.europa.eu/en/emodnet-web-service-documentation) provide regional DTM point samples and projected WMS seabed attributes. Follow [EMODnet reuse terms](https://emodnet.ec.europa.eu/en/terms-use-emodnet-online-services-data-and-data-products) and retained originator restrictions. The seabed request projects only relevant non-personal attributes; it does not download contact fields or polygon geometry. Context is not suitable for navigation or safety at sea.
- **[Nominatim public usage policy](https://operations.osmfoundation.org/policies/nominatim/): the application developer must deliberately choose this public service and remain responsible for compliance.** `/v1/geocode?q=...` is for a submitted place-name search, never autocomplete, scheduled/geographic-grid searches, confidential data or POI extraction. Public requests are cached, identified and spaced at least 1.1 seconds apart in one gateway process; maximum queue 4. The public service permits at most 1 request/sec across the entire app, including all replicas. Run one gateway instance or replace the process-local limiter/cache with a shared gateway before scaling. Set `NOMINATIM_URL` to change provider without an app release; use a managed/self-hosted endpoint for higher volumes. Results contain attribution and the policy link. Do not send private names/addresses or confidential vessel details to it.
- [Open-Meteo terms](https://open-meteo.com/en/terms) and [marine API](https://open-meteo.com/en/docs/marine-weather-api): data attribution does not grant free commercial use of the hosted service. Global waves are disabled by default. `OPEN_METEO_MODE=noncommercial` explicitly enables free-hosted use only for eligible non-commercial deployments; `commercial` requires the customer marine endpoint and server-side API key; `self-hosted` requires your own HTTPS endpoint. API keys are removed from returned source URLs and are never logged. Ocean model sea levels/currents are deliberately not used as coastal clearance evidence.

The API has process-local rate limits and bounded caches; multiple replicas need a shared provider gateway/quota. The app may refresh an active search in the foreground on reconnect or evidence expiry, with at least 60 seconds between attempts. Inactive/background discovery is not polled. Provider cache and product update limits still apply, so a UI refresh does not necessarily generate an upstream request. Core use requires no account or subscription API fallback.

## Persistent evidence cache

`LIVE_CACHE_ROOT` defaults to `./data/live-cache` under the API working directory and is ignored by Git. Mount it on persistent container storage to retain it across container replacement. Cache files use hashes, private file permissions, bounded payloads and an integrity-checked envelope. Writes stage, sync and atomically rename a complete file. The raw-provider cache is capped at 128 records/128 MiB; snapshot/version files at 128 records/64 MiB. Old entries are evicted by age within those limits. The cache contains public source data and the selected geographic requests; it does not contain boat profiles or watch sessions.

An unavailable or partial POI refresh retains prior missing places and marks, each with original source retrieval/expiry. Updated objects use the new source record; old objects are never relabelled fresh. A successful complete empty response can remove stale mapped objects. When all forecast adapters fail, overlapping cached forecast intervals remain labelled cached and retain expiry. Failed EMODnet components can retain old values independently; a successful empty response does not resurrect old context. Freshness and deterministic assessment gates still apply. A cache write failure does not destroy the previous complete file or prevent the returned data being saved by the device.

## Map downloads

`GET /v1/maps/resource?url=...` supports the user-selected offline map downloader. It accepts only HTTPS resources on `tiles.openfreemap.org`, rejects credentials, alternate ports, query strings, fragments and redirects, strips all client headers, sends the project User-Agent, caps each response at 8 MiB, and permits at most 4 simultaneous upstream requests. The client enforces the complete area budget and resumes verified resources. This endpoint is not a generic URL proxy. Public deployments should apply application-level abuse/egress controls.

[OpenFreeMap terms](https://openfreemap.org/tos/) permit bounded offline area downloads with identifying User-Agent and at most 4 parallel requests. The client uses the stricter combined limits of at most 3,000 tiles and 50 MB per selected area. Map tiles are display only; they are never used to establish depth, seabed, restrictions or anchoring suitability. Upstream failures propagate, and an interrupted download preserves the prior complete pack.

## Validation

Run `npm run test -w @anchor-buddy/api` and `npm run typecheck -w @anchor-buddy/api`. Fixture tests exercise real response schemas without claiming that fixtures are live data. `node --import tsx apps/api/scripts/live-smoke.ts` makes one explicitly selected area request against the real providers and validates the resulting RegionPack. It downloads no chart cells or world datasets. Public endpoints can time out; a successful partial response must still explain unavailable evidence.

Live API checks on 2026-11-11 returned 91 places/1 mark/63 forecast intervals for a 2 nm Split area, and 13 places/47 marks/63 intervals for a 3 nm Singapore area. Split also returned a real EMODnet mud classification with its 1985 originator reference; no valid DTM value was returned at that selected point. A separate MET Oceanforecast check near Bergen returned 204 model timesteps including significant wave height 1.3 m. Counts and forecast values are dated observations, not fixed expected product values. Main Overpass was at capacity and Private.coffee timed out; neither is silently used as a retry mirror.
