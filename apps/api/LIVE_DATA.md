# Live area discovery

`POST /v1/regions/discover` takes `{center:[longitude,latitude],radiusNm,name?,from?,until?}`. Radius is 0.25–25 nautical miles; coordinates are rounded to four decimal places; stay is at most 30 days. Dates are ISO timestamps with timezones. The response includes `{pack,providers,notices,requestedArea,partial}`. Provider status fields are `id`, `name`, `status` (`available`, `partial`, `unavailable`, `disabled`, `not-covered`), `message`, and optional `attribution`, `documentationUrl`, `retrievedAt`, `validUntil`, `license`.

This endpoint requests real public data for the selected area. It never substitutes demonstration places when a provider fails. A stable request-area hash identifies the pack; the retrieval timestamp and a content hash identify the version. The API keeps at most 64 recent snapshots in memory for `/v1/search`; mobile persists an installed snapshot independently. A restarted server may require discovery again. Every live snapshot has `validation.status=unreviewed`, explicitly incomplete weather coverage, and no manufactured chart depths, tariffs, tide/current relationships, habitat, jurisdiction or clearance evidence. Shared assessment therefore cannot return a passing anchoring recommendation from live discovery alone. Reviewed regional NOAA analysis packs are a separate ingestion/review workflow. Community seamarks are display features, not complete chart hazards.

MET Norway supplies global point-model wind. NWS raw grid data and active alerts supplement US locations. Source intervals and missing fields are preserved; no forecasts are extended beyond their returned interval. The response can be useful even when some providers fail. A long stay can exceed the weather horizon and remains incomplete. Weather blending prefers an available NWS value, then MET wind; optional marine wave values fill only actual wave intervals. Wave/current/swell gaps are never calm conditions. NWS active warnings do not establish future warning completeness. No coverage rectangle is treated as reviewed spatial evidence.

## Public-service policies

- [MET Norway terms](https://api.met.no/doc/TermsOfService) and [Locationforecast documentation](https://api.met.no/weatherapi/locationforecast/2.0/documentation): CC BY 4.0 attribution, an identifying application User-Agent, four-decimal coordinates, cached responses until `Expires`, conditional revalidation, and bounded traffic. Data is usable commercially under its attribution license. The default source works without accounts or API keys. The gateway identifies the public project URL; end-user IPs are not forwarded upstream.
- [Overpass public-instance guidance](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html): the public server is a shared resource, not a dependable backend for a mass-market app. Development uses small, bounded requests; set `OVERPASS_URL` to an appropriately provisioned managed or self-hosted endpoint for production. `NODE_ENV=production` disables place discovery until this variable is explicitly configured. POST requests include marina, mooring, anchorage and buoy/beacon tags, cap 600 features and retain [OSM attribution/ODbL](https://www.openstreetmap.org/copyright). Fees, depths, access and seabed tags are shown only as unverified notes.
- **[Nominatim public usage policy](https://operations.osmfoundation.org/policies/nominatim/): the application developer must deliberately choose this public service and remain responsible for compliance.** `/v1/geocode?q=...` is for a submitted place-name search, never autocomplete, scheduled/geographic-grid searches, confidential data or POI extraction. Public requests are cached, identified and spaced at least 1.1 seconds apart in one gateway process; maximum queue 4. The public service permits at most 1 request/sec across the entire app, including all replicas. Run one gateway instance or replace the process-local limiter/cache with a shared gateway before scaling. Set `NOMINATIM_URL` to change provider without an app release; use a managed/self-hosted endpoint for higher volumes. Results contain attribution and the policy link. Do not send private names/addresses or confidential vessel details to it.
- [Open-Meteo terms](https://open-meteo.com/en/terms) and [marine API](https://open-meteo.com/en/docs/marine-weather-api): data attribution does not grant free commercial use of the hosted service. Global waves are disabled by default. `OPEN_METEO_MODE=noncommercial` explicitly enables free-hosted use only for eligible non-commercial deployments; `commercial` requires the customer marine endpoint and server-side API key; `self-hosted` requires your own HTTPS endpoint. API keys are removed from returned source URLs and are never logged. Ocean model sea levels/currents are deliberately not used as coastal clearance evidence.

The API has process-local rate limits and bounded caches. It does not implement a distributed public-provider quota; production operators must configure a shared gateway or provider agreements before running replicas. Query coordinates are sent to the selected data services. No background polling, user accounts, personal contact data or subscription API fallback is required.

## Map downloads

`GET /v1/maps/resource?url=...` supports the user-selected offline map downloader. It accepts only HTTPS resources on `tiles.openfreemap.org`, rejects credentials, alternate ports, query strings, fragments and redirects, strips all client headers, sends the project User-Agent, caps each response at 8 MiB, and permits at most 4 simultaneous upstream requests. The client enforces the complete area budget and resumes verified resources. This endpoint is not a generic URL proxy. Public deployments should apply application-level abuse/egress controls.

[OpenFreeMap terms](https://openfreemap.org/tos/) permit bounded offline area downloads with identifying User-Agent and at most 4 parallel requests. The client uses the stricter combined limits of at most 3,000 tiles and 50 MB per selected area. Map tiles are display only; they are never used to establish depth, seabed, restrictions or anchoring suitability. Upstream failures propagate, and an interrupted download preserves the prior complete pack.

## Validation

Run `npm run test -w @anchor-buddy/api` and `npm run typecheck -w @anchor-buddy/api`. Fixture tests exercise real response schemas without claiming that fixtures are live data. `node --import tsx apps/api/scripts/live-smoke.ts` makes one explicitly selected area request against the real providers and validates the resulting RegionPack. It downloads no chart cells or world datasets. Public endpoints can time out; a successful partial response must still explain unavailable evidence.

The initial live smoke on 2026-11-03 returned real MET Norway forecasts, Nominatim locations and OpenFreeMap style data. The public Overpass endpoints timed out from the implementation environment; the app returned an explicit unavailable status with zero substituted places. OSM parsing is covered by fixtures, but a production endpoint must be verified with actual results before relying on place discovery.
